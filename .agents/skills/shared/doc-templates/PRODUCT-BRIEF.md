# Product brief template

What problem the feature solves, for whom, and how others solve it. Recommendations are the agent's; decisions are the user's. Follow the rules in [SKILL.md](SKILL.md).

```md
# Product brief: <feature>

Sources and provenance: <research notes in this folder, interviews, URLs + date read>

## Problem

<The problem from the user's side, in their words where possible. Evidence that it is real, tagged and cited.>

## Who has it

<Segments or personas: who they are, what they are trying to get done (jobs to be done), how often, what it costs them today.>

## Current alternatives

<How people cope today: workarounds, competitors, adjacent tools. Table: alternative | what it does well | where it falls short | source.>

## Prior art worth copying or avoiding

<Specific patterns from comparable products, each linked to a research note.>

## Value and success signals

<What changes for the user if this works. Leading and lagging metrics, with how each would be measured.>

## Scope options

<Smallest version that solves the core problem, then the next increments. Mark the recommended starting scope.>

## Constraints and risks

<Legal, compliance, platform, pricing, dependency, and adoption risks. Riskiest assumptions first, each with how to test it cheaply.>

## Open questions for grilling

<Numbered decisions only the user can make, each with a recommended answer. These seed the first grilling round.>
```
